Lucifer Lab/Journey

Journey

What was tried, caught and fixed.

A result is only as good as the path to it. Here are the wrong turns: an exam that was too easy, a flawed task, a scoring bug and a power study that fooled us once.

TimelineCalibrationLessons

How it got here

Two days, twelve commits, one question.

  1. 11 Nov 2026The lab, built

    Task set, sandbox, versioned memory with rollback, three conditions, a paired bootstrap, three gates, and simulated-agent controls to test the tester.

    commit d8655b1
  2. 11 NovCalibration says the exam is too easy

    Three hosted models scored 100%, 96% and 42% first try with no memory. A flawed task (days_between did not say its inputs were integers) was caught and its spec fixed.

    commit 7be58d6
  3. 11 NovThe power study is corrected

    An early 20-run table said 90% power at 24 tasks. That was a lucky draw; 60 runs gave 72%. The plan now asks for about 48 similar and transfer tasks.

    commit 8868edb
  4. 11 NovTracing and a dashboard

    Every step of every solve is recorded, with a local dashboard to click into any attempt.

    commit c6c090e
  5. 11 NovHarder families, and a scoring bug found

    Four harder families brought the set to 50 tasks. The dashboard exposed a bug: the retention gate picked tasks and measured them on the same runs and mistook luck for forgetting. Selection now uses half the seeds, measurement the other half.

    commit c7b8ee7
  6. 11 NovHidden conventions

    Strong models saturate well-specified tasks, so memory had nothing to improve. 30 convention tasks were added whose rule can only be learned from a failing test.

    commit f92ccb8
  7. 12 NovEverything moves onto CI/CD

    Experiments run on GitHub Actions: one job per seed, a merge step, gates in the job summary, published results committed automatically.

    commit 136a110
  8. 12 NovFirst real result

    Five seeds of qwen2.5-coder:14b: +0.50 first-try improvement, interval +0.30 to +0.70, published with every caveat. Version 1 closed.

    commit 1a88d19

Calibration asks: is there room for memory to help? The first table (3 seeds, baseline only, the older fully specified tasks) found strong models at the ceiling, so no memory effect could show. The second (1 seed, convention tasks) found the opposite problem: a 3B or 7B model cannot apply a hidden convention even when told. The 14B was the first that could fix one after feedback (60%), so it became the subject of the real run.

What was learned along the way

Strong models saturate

96–100% first-try success with no memory leaves nothing to improve. Making tasks more numerous does not help; they must hide something learnable.

Choosing and measuring on the same data fakes results

The retention-gate bug was exactly this. Regression to the mean looked like forgetting until selection and measurement were split across seeds.

Small sets give weak verdicts

About 26 primary tasks detect a real +20 point effect roughly half the time. The first real run has 18, so it is a first look.

Feedback alone fixes most conventions

After one retry the baseline reaches 52%. Any memory gain therefore has to show up on the first try, which is why that is the primary metric.

Simple retrieval was enough

Plain word-matching TF-IDF did as well as anything tried (word pairs, stemming). Semantic retrieval is still untested.

A hosted free tier is not an experiment platform

A side run on a hosted model pointed the same way (+0.44, one seed) but its other seeds hit a daily token cap, so it is not part of the result. The real run moved onto pinned models on GitHub runners.
