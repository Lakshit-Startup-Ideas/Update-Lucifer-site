Does an AI that remembers its mistakes actually get better?

Lucifer Lab is a small, open lab built to answer one question fairly: does an agent with persistent memory solve later, related tasks better than the same model without it? Version 1 has its first real answer.

The method

Same model, same exam, three ways to prepare.

Everything is identical except what the model is allowed to remember. Hidden tests mark every answer, and a failed first try gets exactly one retry with the test output.

A

No memory

The model sits every task cold. This is the honest starting line.

B

Lucifer

Lessons from earlier failures are written to memory, then the three most relevant are shown on later tasks.

C

Wrong notes

A control. It reads the same amount of memory, but the least relevant lessons. If this helped, the effect would be luck, not learning.

Why hidden conventions

The first exam used well-specified tasks and strong models scored 96–100% with no memory, so it could show nothing. Memory only has room to help where a model cannot know something up front but can learn it from feedback, such as a house format or an exact error message. So Version 1 tests exactly that.

Memory you can audit

Memory is a hash-chained store: each lesson points at the one before, so any edit is detectable. Rolling back archives lessons instead of erasing them, and every lesson records where it came from. Every step is also traced, with a local dashboard to click into any attempt.

    Achievements

    What Version 1 took to get right.

    1. The lab itself

      80 tasks (50 pitfall, 30 hidden-convention) with hidden tests, a sandboxed runner, hash-chained memory with rollback, three conditions, a paired bootstrap and three gates. 125 tests pass.

    2. A useless first exam, caught early

      Strong models scored 96–100% with no memory, so that exam could never show an effect. Calibration said so before any claim was made.

    3. A scoring bug found by the dashboard

      The retention check mistook luck for forgetting (regression to the mean). The dashboard exposed it and the gate's selection was fixed.

    4. Everything moved onto CI/CD

      Experiments now run on GitHub Actions: one job per seed, a merge step, gates in the job summary, and published results committed automatically.

    5. First real result · Version 1 closed

      +50 points first-try success over no memory and over wrong notes, interval +30 to +70, on 5 seeds. Published with every caveat.

    Picking a model that has room to learn

    Calibration on the runners, one seed, convention tasks. Small models cannot apply a hidden convention even after feedback, so memory has nothing to add.

    Honest limits

    What this result does not show.

    A "no effect" result would have been published too. These are the reasons to read this one as a first look, not proof.

    The baseline is zero by design

    The conventions are hidden, so no model can pass first try without learning them. The gain is mostly skipping the failed first try. After one retry, no memory already reaches 52%.

    Transfer is weak

    Lucifer helps most where a new task is close to an old one (67%). On looser links it manages 17%.

    Small and single

    One model, 18 scored tasks, 5 seeds, and tasks the author wrote. Replay at 98% is memorisation, not understanding.

    Retention is undecided

    Because the baseline masters no task, the retention gate has nothing to test. It stays inconclusive.

    A side run, not merged

    An earlier hosted run on another model (one seed) pointed the same way, +0.44. Its other seeds hit a free-tier daily cap, so it is not part of the result above.

    What comes next

    More tasks (48+ scored), a second model, a held-out task family never seen during design, and a stronger test of transfer.

    Reproduce it

    Open code, and a run you can start yourself.

    The experiment runs as a GitHub Actions workflow, so no local models and no GPU are needed. Results land in the repository with the report and raw rows.

    Run the lab locally

    # clone, install, run the tests
git clone https://github.com/Lakshit-Startup-Ideas/Lucifer-BenchMarks
cd Lucifer-BenchMarks
python -m venv .venv && .venv/bin/pip install -e .
.venv/bin/pytest

    125 tests, about four minutes.

    Run the experiment on GitHub

    # Actions → Experiment → Run workflow
model     qwen2.5-coder:14b
taskset   convention
seeds     5
publish   true

    One job per seed, then a merge and the three gates in the job summary.

    Before you ask

    Straight answers.

    Is this proof that AI memory works?

    No. It is a first look: one model, 18 scored tasks and 5 seeds. It shows that lessons learned from test feedback get retrieved and used on similar tasks. It does not show broad understanding.

    Why is the no-memory score exactly 0%?

    The conventions are hidden and only revealed by test feedback, so a model that has not seen the feedback cannot know them. That is the point of the exam. It is why the retry numbers are reported next to the first-try ones.

    What is the "wrong notes" condition for?

    It is a control. It gets the same amount of memory but the least relevant lessons. If it matched Lucifer, the benefit would come from having any notes at all, not from the right ones. It scored 0%.

    How do you know the memory was not edited afterwards?

    Each lesson is chained to the previous one by a hash, so a change breaks the chain. Rollbacks archive lessons instead of deleting them, and each lesson records its provenance. The third gate checks all of this on every run.

    Where does it run?

    On GitHub Actions runners (4 CPUs, no GPU), with a pinned Ollama and the model cached between runs. One job per seed, so a full 5-seed run takes a few hours.

    What if the next run shows no effect?

    It gets published the same way. The gates were fixed before the run, and the code and rows are open so anyone can recompute them.
